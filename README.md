# Hackathon Local Toolkit

한국어 Codex 스킬 3개와 읽기 전용 CSV·JSON 검사기. 새로 작성한 범용 지침·코드·합성 예제만 담습니다. 개인 파일·회사 데이터·시험 자료는 포함하지 않습니다.

## 사용 범위

- AI 사용이 허용된 과제 수행 단계에서만 사용합니다. 서술형 평가에서는 AI 사용과 복사·붙여넣기가 금지되므로 이 도구도 사용하지 않습니다.
- 반입은 허용된 본인 공개 GitHub 저장소 경로만 따릅니다. 개인 PC 파일이나 비공개 스킬을 시험 환경으로 옮기지 않습니다.
- 저장소는 결과 통지 전까지 공개 상태로 유지합니다. 실제 반입 절차와 사용 가능 시점은 주최 측 안내를 우선합니다.
- 시험 중 개인 API 키, 외부 AI·데이터 서비스, 외부 전송, Git push, Computer Use 자동화는 사용하지 않습니다. 제공 Codex도 업데이트하지 않습니다.
- 이 도구에는 네트워크 호출, 패키지 자동 설치, 텔레메트리, 자격증명, MCP 서버가 없습니다. 스킬 자체가 권한을 통제하는 보안 장치는 아닙니다.

## 처음 가져오기와 나중에 갱신하기

아래는 **일반 터미널** 명령입니다. 주최 측이 허용한 공개 저장소 반입 시점과 작업 위치에서만 실행하세요. 웹 화면에 별도 가져오기 기능이 있다면 그 절차를 따르세요.

처음에는 저장소를 새 폴더로 내려받습니다.

```sh
git clone https://github.com/jaesung0804/hackathon-local-toolkit.git
cd hackathon-local-toolkit
```

이미 내려받은 폴더를 갱신할 때는 그 폴더 안에서 실행합니다. `--ff-only`는 서로 다른 수정 이력을 억지로 합치지 않습니다. 충돌이나 로컬 수정 경고가 나오면 강제 초기화하지 마세요.

```sh
git pull --ff-only
```

`clone`은 첫 다운로드, `pull`은 기존 복사본 갱신입니다. 둘 다 네트워크를 사용하므로 허용된 반입 때만 실행합니다. 과제 수행 중 자동 갱신은 하지 않습니다. `push`는 내 변경을 GitHub로 보내는 명령이며 시험 중에는 사용하지 않습니다.

## Codex에서 스킬 사용하기

일반 Codex 구조는 현재 작업 위치부터 저장소 루트까지의 `.agents/skills`를 탐색합니다. 이 폴더에서 제공된 Codex를 열면 3개 스킬을 찾을 수 있습니다. [공식 스킬 안내](https://developers.openai.com/codex/skills/)

시험 과제 저장소가 별도라면 이 저장소를 받았다는 것만으로 그 과제에 스킬이 자동 적용되지는 않습니다. 허용된 반입 절차로 공개 저장소의 스킬 폴더를 과제의 `.agents/skills` 아래에 배치하거나, 과제 대화에서 가져온 `SKILL.md`의 정확한 경로를 지정해 읽도록 요청하세요. 기존 파일은 덮어쓰지 마세요. 개인 PC에서 가져오는 방식은 사용하지 않습니다.

**Codex 대화 입력칸**에서 `/skills` 또는 `$`로 목록을 확인하고 다음처럼 요청합니다. 이것은 일반 터미널 명령이 아닙니다.

```text
$clarify-task 제공된 README와 문제 요구사항으로 목표와 완료 조건을 정리해줘.
$check-work 지정한 과제 폴더에서 정상·경계·오류 사례를 실행하고 결과를 보여줘.
$record-evidence 지금까지 실제 결정과 실행 증거를 과제 폴더의 work-log.md에 기록해줘.
```

스킬이 목록에 없으면 파일 배치와 제공 버전의 지원 여부를 확인합니다. 플랫폼 설정을 변경하거나 Codex를 업데이트하지 마세요. AI 실행 결과와 사람 확인은 별도 항목이며, 사용자가 직접 확인했다고 명시한 경우에만 사람 확인으로 기록합니다.

## 검사기 실행하기

Python **3.9 이상**, 표준 라이브러리만 필요합니다. 이미 제공된 `python` 또는 `python3`를 사용합니다. 아래 명령은 저장소 루트 기준입니다. `--root`는 읽기를 허용할 작업 폴더, 파일 경로는 그 폴더 기준입니다.

```sh
python scripts/check_data.py csv sample.csv --root examples
python scripts/check_data.py json sample.json --root examples
python -B -m unittest discover -s tests -v
```

CSV 예제는 문제를 일부러 넣었습니다. 정상 출력은 `rows: 4`, `missing_by_column: [0, 1, 1]`, `duplicate_rows: 1`, `bad_width_count: 1`, 종료 코드 **1**입니다. JSON 예제는 `ok: true`, 종료 코드 **0**입니다. 테스트 명령은 문제를 올바르게 탐지했는지를 검증하므로 성공하면 종료 코드 **0**입니다.

실제 입력이 `과제폴더/data/input.csv`라면 `--root`에 과제폴더를, 파일 인수에 `data/input.csv`를 지정합니다. 원본은 읽기만 하고 보고서는 터미널에 출력합니다. 결과를 파일로 저장하려면 원본과 다른 파일명을 사용하고 과제 폴더 안에만 저장하세요.

| 검사 | 의미와 범위 |
| --- | --- |
| CSV | 쉼표 구분, 첫 레코드를 헤더로 사용. 공백만 있는 셀과 부족한 열을 결측으로 계산. 빈 파일·헤더만 있는 파일·빈/중복 헤더·열 수 불일치도 보고 |
| 중복 | 모든 셀의 원문이 동일한 데이터 행의 추가 반복 횟수. 특정 키 기준 중복은 검사하지 않음 |
| 행 번호 | 헤더를 제외한 논리적 데이터 레코드 번호. 따옴표 안 줄바꿈이 있으면 물리적 줄 번호와 다를 수 있음 |
| 결측 결과 | 헤더 순서에 따른 열별 개수. `0`, `null`, `NA`라는 문자열은 결측으로 간주하지 않음 |
| JSON | 문법 검사. NaN·Infinity는 거부. 스키마, 업무 의미, 중복 객체 키는 검증하지 않음 |
| 파일 제한 | UTF-8/BOM, 최대 10 MiB, 로컬 일반 파일. 폴더 밖 경로·밖을 향한 심볼릭 링크·하드 링크·UNC 경로 거부 |
| 종료 코드 | `0`: 해당 검사 통과, `1`: 품질 문제/문법 오류, `2`: 사용법·경로·인코딩·크기·실행 오류 |

대용량 파일이나 다른 인코딩·구분자에는 맞지 않습니다. 파일 경계 검사는 편의 보호장치이며 운영체제 샌드박스가 아닙니다. 실행 중 입력 경로나 링크를 다른 프로세스가 바꾸지 않는 로컬 작업을 전제로 합니다. 이 검사를 통과해도 과제 전체의 정확성을 보장하지 않습니다.

## JSON 설정, Skill, MCP는 무엇이 다른가요?

| 구분 | 하는 일 |
| --- | --- |
| JSON | 데이터를 적는 형식. 어떤 앱의 설정 파일일 수 있지만 파일만으로 프로그램이 설치되지는 않음. `sample.json`은 설정이 아니라 합성 데이터 |
| Skill | `SKILL.md`에 적힌 작업 지침. 이번에는 요구 정리·검증·기록의 3개 지침 |
| 검사 스크립트 | Python이 실행하는 실제 코드. 이 저장소는 로컬 CSV·JSON 검사만 수행 |
| MCP | AI가 별도 도구 서버를 호출하는 연결 방식. 서버 실행 코드·의존성·연결 설정이 필요하며 이번 도구에는 포함하지 않음 |

## 검증 범위

합성 테스트로 정상·빈 입력·누락·중복·열 수·따옴표·JSON 오류·인코딩·파일 크기·작업 폴더 경계를 확인할 수 있습니다. 테스트가 만드는 임시 파일은 `tests` 아래에 생성했다가 정리합니다. 심볼릭 링크나 하드 링크 생성 권한이 없으면 해당 테스트는 `skipped`로 표시합니다.

실제 시험 플랫폼의 스킬 탐색, 명령 실행, 반입 UI는 **검증하지 않았습니다**. 이 저장소는 범용 Codex 구조이며 제공 플랫폼에서의 작동을 보장하지 않습니다. 테스트 실행 사실과 미검증 범위를 구분해 기록하세요.
