# 실제 실행으로 검증

사용자가 지정한 작업 폴더 안의 코드와 입력만 사용한다. 원본 데이터는 변경하지 않는다. 필요한 추가 입력은 그 폴더 안에 합성 예제로 만든다.

1. 완료 조건과 기존 테스트·실행 방법을 확인한다.
2. 관련 있는 정상 사례, 경계 사례(빈 입력, 최소·최대값, 날짜 경계 등), 오류 사례(필수 열 누락, 잘못된 형식 등)를 고른다. 해당하지 않는 사례를 억지로 추가하지 않는다.
3. 기대 결과를 먼저 정하고 실행한다. 실행 명령, 종료 코드, 실제 관찰 결과를 함께 남긴다. 데이터를 불필요하게 출력하지 않는다.
4. 실패를 수정했다면 실패 사례와 영향을 받는 핵심 정상 사례를 다시 실행한다.
5. `통과 / 실패 / 실행 불가 / 미검증`을 구분한다. 명령을 제시하거나 코드를 읽은 것만으로 통과라고 쓰지 않는다. 오류를 잘 거부한 경우에는 예상 종료 코드와 일치했는지 확인한다.

CSV·JSON 기본 검사가 필요하면 이 저장소의 `scripts/check_data.py --help`를 확인한 뒤 `--root`에 실제 과제 폴더를 지정한다. 검사 결과는 문법·기본 데이터 품질 점검이며 업무 규칙이나 전체 기능 검증을 대신하지 않는다.

AI가 실행한 결과와 사람 확인을 분리한다. 사용자가 직접 확인했다고 명시한 항목만 사람 확인으로 기록하고, 나머지는 `사람 확인: 미확인`으로 둔다.

AI 사용이 허용된 과제 단계 전용이다. 서술형 답변 생성, 외부 AI·API 키·외부 데이터 서비스·외부 전송·Git push·Computer Use 자동화, Codex 업데이트나 패키지 자동 설치를 하지 않는다. 필요한 도구가 없으면 우회 설치하지 말고 실행 불가로 보고한다.
